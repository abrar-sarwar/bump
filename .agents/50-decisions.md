# Decisions already made

Append, never rewrite. If you disagree with one, raise it with the human rather
than silently reversing it.

Format: `## <decision>` then **Why** and, where useful, **What would change it**.

---

## The site uses the wordmark PNG artwork, not a font
**Why:** the brand face is Horizon, which is not licensed here. Using the
supplied artwork (ivory keyed to transparency) matches the brand exactly with no
licence. Headings use Archivo (Google Fonts, variable weight + width) chosen to
sit close to the heavy wide lettering.
**What would change it:** licensed Horizon `.woff2` files, or an SVG export of
the wordmark (which would also remove the ~2000px resolution ceiling).

## The hero wordmark is revealed by a clip-path mask, not by fading or scaling
**Why:** it must appear to *grow out of the point where the phones met*. Masking
keeps letterforms undistorted at every frame; `scaleX` would squash them. The
closed state is duplicated in `BumpHero.css` so it cannot flash before GSAP runs.

## Desktop and mobile hero are separate compositions
**Why:** at 82vw each the phones already overlap horizontally on mobile, so a
side-by-side meeting is impossible. Mobile closes along **y** (blue down from
upper-left, orange up from lower-right, corner to corner) and parts back along
the same axis so the tagline gets a clean band. Desktop closes along **x**.

## Contact geometry is asymmetric on purpose
**Why:** these are photographs. The blue phone case spans 63.8%–99.8% of its
image width, the orange ~0.2%–48%. The tuning is against those silhouettes, so
symmetric numbers would look wrong. Do not "fix" the asymmetry.

## Reloading partway down the page returns you to the top
**Why:** a restored mid-pin scroll position is the usual cause of broken pinned
layouts. Deliberate, not a bug.

## The 860px breakpoint is a judgement call
**Why:** between roughly 700 and 860px the desktop composition would also work.
Documented honestly as a judgement rather than presented as a measurement.

## No em dashes in shipped web copy
**Why:** a house style decision, enforced by `scripts/verify-reveal.mjs`.

## The site shows no download link, waitlist, or App Store badge
**Why:** none of those exist. Only real destinations ship. The CTA links to an
in-page anchor and to the public repo.

## Example match data is fictional, labelled, and self-validating
**Why:** showing a fabricated "overlap" would undercut the product's entire
claim. `EXAMPLES` is the single source of truth for both the highlighted
interest and the opener so they cannot drift, and `VALID` refuses to render any
example whose shared interest is missing from either profile.

## The backend never returns fallback content on a success status
**Why:** the app must be able to label results honestly. If Grok output fails
validation the request fails (502) and the **app** substitutes a local fallback,
labelled as local. A server-side fallback would make "Grok said this"
unfalsifiable.

## The backend is zero-dependency
**Why:** it holds the xAI key. Smallest possible supply chain.

## BUMP rejects ambiguous bumps rather than guessing
**Why:** motion tells a phone *that* it was tapped, not *who* tapped it. A guess
that is wrong is worse than a refusal. Manual picks are recorded *as* manual
picks. The rejection rate is reported separately from accuracy in `RESULTS.md`,
because rejecting everything would otherwise look like perfect accuracy.

## `assets-source/` originals are never edited
**Why:** derivatives are regenerated by `python3 web/assets-source/extract.py`,
which keys the white studio background, keeps the largest connected blob and
fills interior holes so the camera plateau and the gaps between fingers survive.
Each phone and hand stay one layer at the photograph's own proportions. Nothing
is stretched or re-posed.

## `.agents/` is git-ignored
**Why:** it is local AI scratch context shared between tools on this machine,
not part of the product, and it is not the repo owner's to receive in a PR.

**Superseded 2026-09-26:** the human explicitly asked to stage and push
`.agents/` with the `ios-mockup-vis-charan` branch. It is now tracked. Keep
secrets and tokens out of this public folder.

## Material Design 3 is the primary design language for `web/` (2026-09-26)
**Why:** the human's call. Adopted as a **token system only**: MD3 colour roles,
type scale, shape scale, elevation, state layers and motion drive `tokens.css`,
while the components stay hand-built CSS. The whole landing page has two buttons
and three dot controls, so a component swap would have added custom-element
plumbing for almost no benefit.
**What would change it:** if the site grows real UI (forms, menus, dialogs),
revisit `@material/web` components. The packages are already installed.

## MD3 owns the neutrals. The brand ivory is gone. (2026-09-26)
**Why:** the human chose MD3-derived neutrals over keeping the warm ivory. MD3
derives neutrals from the seed hue, so the page surface moved from the
artwork-sampled ivory `#fff9f0` to the algorithmic cool `#fdfcff`, and
`--ivory-deep` became `--md-sys-color-surface-container-low` `#f4f3f7`. This was
flagged before it was applied: it is the most distinctive thing the old palette
had, traded deliberately for scheme orthodoxy.
**What would change it:** MD3 supports overriding the neutral palette
independently of the seed, so ivory can be restored as a surface family without
abandoning MD3. That is a one-file change in `tokens.css`.

## Colour roles are generated, never hand-picked
**Why:** MD3 colour is algorithmic. Every role is derived from the single seed
`#73a9f5` in HCT space. Hand-editing one role desynchronises it from the
algorithm and breaks the contrast guarantee between each `x` / `on-x` pair.
Change the seed in `scripts/gen-md3-tokens.mjs` and regenerate instead.

## The hero stays outside MD3
**Why:** its geometry is tuned against photograph silhouettes and its motion is
scrubbed to scroll position, which must stay linear. MD3 motion tokens govern
component state transitions, not a scroll-driven scene. Only the hero's colours
were remapped to MD3 roles.

## `--brand-phone-orange` is deliberately outside the MD3 scheme
**Why:** it samples the photograph so tints can be keyed to the artwork. It is
not an MD3 role and must never be UI chrome. Same rule as the old `--orange`.

## `@material/web` components are used on the page (2026-09-26)
**Why:** the human asked for more of the Material kit to liven the site up.
Supersedes the "tokens only" half of the MD3 decision above. Hand-built `.btn`
was removed rather than kept alongside: one button system, not two.
Components read the same generated `--md-sys-*` roles, so nothing new to sync.

## Material Symbols load as a Google Fonts subset, not from npm (2026-09-26)
**Why:** the npm font is 4 to 5 MB for ~20 icons. The subset is tiny.
**What would change it:** a need for icons chosen at runtime.

## Desktop hero phones are 60vw and uncapped (2026-09-26)
**Why:** at 46vw the cropped wrist of each arm was visible at contact. The
human asked for the hands to be zoomed so they do not cut off. Uncapped on
ultrawide because a capped image is narrower than the timeline assumes, which
brings the wrist back on screen. Softness on 2700px+ screens is the trade.

## The hero has faint background detail (2026-09-26)
**Why:** the human asked for very low-opacity detail on the landing. MD3 shape
vocabulary (cookie, clover, sunny, flower, pill) plus conversation glyphs and a
dot grid, all at 6 to 16% of a role colour. Moves only with scroll.

## Everything below the hero is folk.com-inspired (2026-09-26)
**Why:** the human asked for the rest of the site to mimic folk.com, hero
excepted. Measured values live as `--folk-*` in tokens.css: page `#f5f6f8`,
ink `#1f2a2f`, a rounded system font stack, frosted cards with layered soft
shadows, glossy orbs, pill tabs, pastel bento washes. BUMP's MD3 primary
stays the accent. Supersedes MD3 as the language *below the hero*; the hero
keeps MD3. `@material/web` below the hero is now just `md-icon`.

## Below-hero copy renders lowercase, via one CSS line (2026-09-26)
**Why:** folk's voice, and the master doc's draft copy is lowercase too.
Source text stays sentence case; `text-transform: lowercase` on
`.folk-section` does it. Delete that line to revert. The closing panel is
deliberately NOT a folk section (sentence case, MD3 primary, solid colour).

## Walk-by ("StreetPass") appears on the site, labelled as in the works (2026-09-26)
**Why:** the human said the team will try it and wants it shown; the name
will change (`NAME` constant in WalkBy.tsx, placeholder "walk-by"). Copy
claims only what the master doc describes and says "not in the app yet".
The HowItWorks "BUMP never scans the room for strangers" line was removed in
the same pass (the steps were simplified), so the site no longer contradicts it.

## iOS UI is designed in an HTML mockup, then ported to Swift
**Why:** the human has no Mac, so SwiftUI Previews and the Simulator are out of
reach. Renting a Mac (Scaleway, MacinCloud, AWS) and CI screenshots were looked
at and turned down: this is a hackathon project and has to be quick and free.
`ios-mockup/` is plain HTML/CSS/JS, no build step, kept apart from `ios/` so
design work never conflicts with Swift work. The human accepted that it will
differ slightly from real iOS rendering.
**What would change it:** access to a Mac with Xcode 26.

## The app mockup's MD3 is built from tokens, not @material/web
**Why:** the mockup exists to be ported to SwiftUI. @material/web Lit elements
have no Swift counterpart, so each would be reimplemented anyway; token-built
CSS components map one-to-one onto SwiftUI styles. Colour is shared with the
web scheme so site and app are one system.
**What would change it:** the app moving to a web or cross-platform stack.

## The app mockup follows the live site, with the brand kept exactly (2026-09-26)
**Supersedes** "The app mockup's MD3 is built from tokens" as the *look*
(components are still built from tokens, not @material/web). After a plain MD3
pass ("super generic") and an M3 Expressive attempt, the human asked for heavy
inspiration from the live site (`web/`, read-only). Then, when that went "too
far into folk": KEEP THE BRANDING THE SAME, LOGO SHOULD NOT CHANGE.
**So:** the wordmark is the Horizon artwork PNG, never a font; Archivo;
sentence case (not the sections' lowercase); the site's MD3 colour scheme; the
site's card language (frosted cards, orbs, pill rows, tags, bubbles, backdrop,
the shared badge). Drawn phones, not the hand photographs.
**What would change it:** the human changing the brand, or the site's look.

## Tutorial "See what you share" is the shared badge alone (2026-09-26)
**Why:** the human's sketch, then "DONT LITERALLY JUST ADD THE MESSAGE THEM":
no card, no outline, no "Message them?" (BUMP has no messaging; do not invent
it). The badge pops up and cycles several interests. Morph speed 0.4x the
site's (23s loop). Morph without baked rotation (it shrank; see 31-ios-mockup.md).
